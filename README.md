# hxwl-04 乳牙治疗计划台

在原根管看板基础上扩展的儿童牙科乳牙治疗计划台：按牙位登记患儿、治疗阶段、预计次数与本次监护人，家长确认后才能推进；疼痛/肿胀转急诊保留原计划，连续两次未到诊进入联系名单。

## 技术栈

React + Vite + TypeScript + CSS

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5104

## 分层结构（记录 / 判断 / 页面分开）

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 记录 | `src/types.ts` | 牙位治疗计划的数据结构（阶段、到诊、监护人、急诊、联系安排、历史） |
| 记录 | `src/storage.ts` | localStorage 持久化，重新打开后阶段、到诊次数、联系安排都还在 |
| 记录 | `src/seed.ts` | 示例数据（治疗中 / 转急诊 / 联系名单 / 已完成） |
| 记录 × 判断 | `src/store.ts` | 所有状态变更的唯一入口：先过规则、再改记录、追加历史并落盘 |
| 判断 | `src/rules.ts` | 纯函数规则：能否到诊/确认/推进/完成、急诊冻结、爽约阈值、状态派生 |
| 页面 | `src/App.tsx`、`src/components/*` | 指标、筛选、登记表单与牙位卡片，只展示和派发动作 |

## 业务规则

1. **每牙位一条计划**：患儿、诊断、当前阶段（初诊登记 → 局麻隔湿 → 开髓 → 清理冲洗 → 封药 → 充填 → 预成冠修复 → 完成）、预计次数、本次监护人。
2. **监护人临时更换**：卡片上可直接改本次陪同人（姓名/关系/电话）；换人后确认自动作废，必须由本次监护人重新确认。
3. **家长确认才推进**：前台先「登记到诊」（到诊次数 +1），家长确认后才能推进下一步；推进后本次到诊与确认重置，下次复诊重新登记。
4. **疼痛 / 肿胀转急诊**：登记表现后本次转急诊，原计划冻结保留在当前阶段；急诊结束回台后解冻，阶段不变、等待重排。
5. **连续两次未到诊**：自动进入联系名单（不能推进、不能算完成）；可记录联系方式、计划/实际联系时间与跟进备注。仅确认重排不脱离名单，须下次实际到诊后才移出并清零爽约计数。
6. **不能直接算完成**：未到诊、未确认、有未处理爽约均禁止完成；完成要求走完预成冠修复阶段且本次到诊 + 家长确认。
7. **留痕与持久化**：每次操作写入操作记录；全部数据存 localStorage，刷新/重开浏览器不丢。
